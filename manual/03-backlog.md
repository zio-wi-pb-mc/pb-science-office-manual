# Backlog i zadania

## GitHub Project

Wspólny backlog znajduje się w GitHub Project. Każdy może zgłosić Issue, ale wejście zadania do `Ready`, jego priorytet i zakres MVP są ustalane podczas planowania z leadami i prowadzącym.

## Statusy

- `Backlog` — pomysł lub zadanie wymagające doprecyzowania,
- `Ready` — gotowe do podjęcia,
- `In progress` — aktualnie realizowane,
- `Review` — implementacja gotowa do przeglądu,
- `Test` — oczekuje na weryfikację,
- `Done` — spełnia Definition of Done,
- `Blocked` — zadanie zablokowane.

## Priorytety

- `MVP` — wymagane do pierwszego działającego wydania,
- `P1` — ważne rozszerzenie po MVP,
- `P2` — dalsze usprawnienie.

## Jak bierzesz zadanie

1. Wybierasz zadanie `Ready` uzgodnione z leadem.
2. Zostajesz przypisany jako Assignee.
3. Zmieniasz status na `In progress`.
4. Tworzysz branch powiązany z numerem Issue.
5. Po wykonaniu otwierasz Pull Request.
